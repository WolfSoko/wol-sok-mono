# Spec #2842: nx-aws-cdk-v2: apps generated before #2835 keep the failing main.test.ts

Found in the review of [PR #2840](https://github.com/WolfSoko/wol-sok-mono/pull/2840)
([#2835](https://github.com/WolfSoko/wol-sok-mono/issues/2835)). Related:
[#2832](https://github.com/WolfSoko/wol-sok-mono/issues/2832),
[#2831](https://github.com/WolfSoko/wol-sok-mono/issues/2831).

## Goal

A workspace with apps generated by `@wolsok/nx-aws-cdk-v2` 4.1.2 or older gets
their starter `src/main.test.ts` fixed by `nx migrate`, the same way 4.1.3
generates it: the test reads the template's `Resources` with `{}` as default
and acknowledges `CloudFormation-Validate::F0001` on its stack. Tests the user
changed stay as they are, and the migration names the ones that still hold the
failing assertion, with the change to make by hand.

Every published version up to 4.1.2 generated one of two starter tests
(checked in the npm packages 1.3.0, 2.0.0, 2.7.0, 3.0.9, 4.0.0, 4.0.30, 4.1.2):

- **legacy** (1.x to early 2.x): `test('Empty Stack', …)` with
  `Template.fromStack(stack as Stack).templateMatches({ Resources: {} })` and
  `// WHEN` / `// THEN` comments;
- **current** (2.7.0 to 4.1.2): `describe('<ClassName>', () => it('synthesizes an empty stack', …))`
  with `Template.fromStack(stack).templateMatches({ Resources: {} })`.

Both fail on current aws-cdk-lib with _"Missing key 'Resources'"_.

## Non-goals

- No change to tests the user edited, beyond a warning.
- No change to the generator's template (fixed in #2835) or to `AppStack`.
- The e2e synth failure stays with
  [#2831](https://github.com/WolfSoko/wol-sok-mono/issues/2831).

## Decisions

1. **A migration, not only a note.** `nx migrate` is how a plugin repairs what
   it generated; a note alone leaves every consumer to find the failure first.
   The README gets a short "Upgrading" section as well, for tests the migration
   leaves alone.
2. **Rewrite only an untouched starter test.** A file counts as untouched when,
   after normalising what a formatter changes (whitespace, quote style,
   semicolons, trailing commas), it equals one of the two known starter tests
   with any describe name and any stack id. Anything else is the user's code.
3. **Keep the names the file has.** The rewritten test keeps the stack id the
   old one passed to `AppStack` and, for the current shape, its describe name;
   the legacy shape gets the project's class name, as the generator would give
   it today. The project may have been renamed since, so the file wins.
4. **Look at every project, guarded by the content.** The migration checks
   `<root>/src/main.test.ts` of every project. The executor names changed over
   the plugin's life (`@ago-dev/…` before `@wolsok/…`), and an exact match of
   the starter test is a stronger guard than any of them.
5. **Warn about edited tests that still fail.** A `src/main.test.ts` that is no
   starter test but still holds `templateMatches({ Resources: {} })` gets a
   `logger.warn` naming the file and the replacement assertion.
6. **Version 4.2.0, a `feat` commit.** `nx release` bumps the minor version
   for a `feat`, and `nx migrate` runs a migration whose version lies above
   the installed one up to the target, so users on 4.1.3 who generated their
   apps earlier get it too.
7. **Raise aws-cdk-lib with the migration, not gate the rewrite on it.** The
   new test imports `Validations`, which old aws-cdk-lib may lack. A
   `packageJsonUpdates` entry at 4.2.0 raises `aws-cdk-lib` to the generator's
   `CDK_LIB_VERSION` (`^2.265.0`) where the workspace names an older one
   (`alwaysAddToPackageJson: false`), so the migration always rewrites an
   untouched starter test. A gate that only warned on older versions would
   leave the test to break on the workspace's next aws-cdk-lib update, when
   `nx migrate` no longer runs this migration (manager's decision on request
   523 of 2026-11-07, after the `/simplify` pass on
   [PR #2849](https://github.com/WolfSoko/wol-sok-mono/pull/2849)).
8. **The migration's result is run, not just compared.** Its spec writes each
   old starter test into a generated app, runs the migration and then runs the
   rewritten test against the workspace's aws-cdk-lib, with the loader the
   `generated-test.spec.ts` of #2835 uses, moved into a shared test helper.

## Acceptance

1. `migrations.json` lists the migration at version `4.2.0`, and `nx migrate`
   would find it (factory path resolves in the built package).
2. An untouched starter test of either shape, also in double-quote and
   semicolon-free formatting, is rewritten; the rewritten test passes against
   the workspace's aws-cdk-lib without a `CloudFormation-Validate` warning.
3. The rewritten test keeps the old stack id (and describe name, where it had
   one).
4. An edited test is left byte for byte; one that still holds
   `templateMatches({ Resources: {} })` is named in a warning.
5. A project without `src/main.test.ts` and a workspace without CDK apps pass
   through without change.
6. `packageJsonUpdates` at 4.2.0 raises `aws-cdk-lib` to `CDK_LIB_VERSION`
   without adding it where it is missing.
7. The README describes the migration, the version bump and the manual change.
8. `nx test nx-aws-cdk-v2`, `nx build nx-aws-cdk-v2`, `nx lint nx-aws-cdk-v2`
   and `nx format:check` pass.
