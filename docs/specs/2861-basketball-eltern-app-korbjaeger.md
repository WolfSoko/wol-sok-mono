# Spec: Basketball-Eltern-App (Korbjäger)

Issue: [#2861](https://github.com/WolfSoko/wol-sok-mono/issues/2861). Domain language: the "Basketball-Eltern-App" section of `CONTEXT.md` (added by [#2860](https://github.com/WolfSoko/wol-sok-mono/pull/2860)). The issue is the full product spec (problem, 45 user stories, implementation and testing decisions); this file fixes what the build needs on top of it and does not repeat the stories.

## Goal

An installable, `noindex` PWA on `korb.wolsok.de` where an **Elternteil** follows **Meine Teams**, marks **Kinder** in a **Kader** and sees per **Kind** the next **Spiel**, the last result and the **Kader** flag; per **Team** all **Spiele** of the **Saison** across its **Ligen** with each **Tabelle**; per **Spiel** score, quarters, both **Kader** and **Spielerwerte** where recorded. Data comes from the DBB's public JSON API through an allowlisted, caching proxy of the app's own. Works without an account; Google sign-in syncs the selection.

## Non-goals

As the issue's "Out of Scope": no push or ICS, no Android app, no player search or player pages, no data entered by parents, no older Saisons or non-DBB leagues, no English, no ads or analytics, no public link (portfolio, sitemap) before the DBB has agreed.

## Acceptance

1. Lib: Jest specs on anonymised fixtures cover Vorrunde + Hauptrunde merged by `teamPermanentId`; Spielerwerte recorded vs. roster-only (all zeros → "not recorded") vs. no boxscore; Anonyme Spieler as a type that cannot be marked; cancelled and forfeited Spiele; envelope `status` `0`/`1`/`-1`; Liga list paging through `wam/liga/list`. `seasonTeamId` never appears in a domain type.
2. No fixture contains a real person name or id (the anonymiser's spec checks the output against the input's names).
3. Proxy: allowlisted paths pass; other paths and non-numeric ids give 404/400; success carries the cache headers, errors none; upstream timeout and 5xx give 502 JSON; DBB `status:"1"` gives 404; no cookie forwarded either way; the Liga search is a GET.
4. `Auswahl`: one spec suite passes against both adapters; first-sign-in merge without duplicates; Firestore rules tested on the emulator (owner only, field allowlist, list caps, nickname cap, delete allowed).
5. Screens (component specs against fakes): overview ordered by next Spiel, Teams without Kind shown; Kind highlight across Teams and Saisons by person id; "keine Spielerwerte erfasst" instead of zeros; "noch kein Spielbericht"; season-end hint (no upcoming Spiel, last one more than 14 days past) offering the Verein's Teams; Anonyme Spieler not markable; cancelled/forfeited and moved Spiele shown as such; Halle with navigation link; home/away told apart.
6. Account: sign in, sign out, delete account (document, then auth user).
7. PWA installable (manifest, service worker); last good data shown with its age offline; clear message when the DBB is unreachable; DBB source note saying the data may lag by a few minutes, and the Spielerwerte of a finished Spiel by about an hour.
8. `/privacy` and `/impressum` name the provider from `SITE_OWNER`; the privacy policy covers Google sign-in, the Firestore document, device storage, Hosting logs and deletion.
9. Every page `noindex`; Hosting sends `X-Robots-Tag: noindex`; `robots.txt` allows crawling; README explains the missing sitemap.
10. E2E (Playwright, server through the Nx serve target, DBB base URL on a fake server with the fixtures): set up a Team → mark a Kind → overview shows the next Spiel and the Kader flag.
11. `typecheck-specs` target on the app and the lib; `lint`, `lint-templates`, `test`, `build` green.
12. Deploy: `deploy` target in the `non-cdk` leg of `deploy.yml`, `predeploy` with `--legacy-peer-deps=false` kept by `firebase-deploy.spec.ts`; CNAME in a CDK stack `korbjaeger-cdk`.

## Open questions

Answered on 2026-11-08: `korbjaeger` / `korb.wolsok.de` is the working name in code, with the Firebase project id and the domain in one place each; one PR per sub-issue; the deploy waits for the owner's Firebase project ([#2865](https://github.com/WolfSoko/wol-sok-mono/issues/2865)), whose id, domain and secret names are asked for when the deploy ticket starts; `robots.txt` allows crawling (see Decisions).
