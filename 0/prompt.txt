  1. libs/public/spa-cdk-stack/src/lib/spa/spa.construct.ts:336-343 (with apps/portfolio-cdk/src/main.ts:10-15 and :40-53)
     Summary: the change adds a second workaround for the same root cause instead of fixing that cause.
     - The root cause is that CloudFront with an S3 REST/OAC origin resolves no folder index (`/x` and `/x/` never reach `x/index.html`).
     - portfolio-cdk already works around this in the app. It uploads every page a second time under its bare key, needs the `pagesByDepth` per-depth uploads so the `blog` file does not block the `blog/` folder, and adds the `noCacheFiles` entries for every page.
     - This PR now adds a CloudFront Function in the lib that covers only the trailing-slash half.
     - Simpler, more general fix: make the same viewer-request function the lib's "folder index" option. It would answer `/x/` with a 301 to `/x` (as now) and rewrite an extension-less `/x` to `/x/index.html`.
     - This still keeps one URL per page. The spec's reason for rejecting a rewrite ("one page under two URLs") applies only to rewriting `/x/`, not `/x`.
     - Non-prerendered SPA routes still miss, get the 403 and fall back to `/index.html` as before.
     Concrete cost of the current design:
     - Two mechanisms in two layers stay for one problem: the app's duplicate uploads plus the lib's redirect.
     - Every page is stored and invalidated twice.
     - `prerenderedPages`/`pagesByDepth` and their tests stay alive only to work around the missing index.
     - Any other prerendered site using `@wolsok/spa-cdk-stack` has to copy that app-level upload trick to benefit from `redirectTrailingSlash`, because the option is only correct when bare-path objects exist (the README even says so).
     - If folder-index resolution were in the lib, the portfolio's duplicate upload could be deleted in the same PR, or in a follow-up issue if you want to keep this PR small.
