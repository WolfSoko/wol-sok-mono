  ## Findings
  
  1. **bug (medium, please confirm on a device)** — `online-room.component.ts:544-548`, which calls `game-state.service.ts:782` → `updateSetup` (`:770`) → `respawnIfIdle` (`:720`) → `initOnline` (`:573`).
     - **What is wrong:** `END` is not `isMatchOn`, so `isIdle()` is true while the result is open. Every host pick in the result dialog therefore calls `initPlayers` → `initOnline`, which re-plans the match, calls `recorder.begin` and `playerService.init`, and spawns fresh colonies.
     - **Same on the guest:** the `setup` event arrives as a `patch` in `applySeat` (`:225-227`) and calls `respawnIfIdle` too.
     - **Failure:** a match ends on Meltdown and the host taps Petri Dish in the result dialog. On both devices the finished board under the result is replaced by a new Petri Dish spawn. That breaks the invariant stated at `:248` ("A match it ended stays on the board under its result until reset").
     - **Why it is new:** before this PR nothing could change the online setup in the `END` state.
     - **Fix:** skip the respawn while `currentState === END`, or hold the pick until the reset.
  
  2. **bug (low/medium)** — `winner.component.ts:136-139`.
     - **What is wrong:** the played level is frozen only while `state.online() !== null`. Once the connection goes, `level` falls back to `state.level()`, which is the device's own `levelId` again.
     - **On the host** that `levelId` is the last level it picked in the room.
     - **On the guest** it is the level it was seated on when it connected, because `setup` events patch only `online.levelId`.
     - **Failure:** after a Meltdown match the host picks Petri Dish, then the opponent closes the tab. The host's result now says "Petri Dish" under the headline. The guest's says whatever it had before connecting. `upcoming` and the boss headline (`:615`) follow the wrong level too.
     - **Forfeit case (not new):** `endOnline` sets `online: null` right after `endMatch`, so the component is built with `online === null` and never freezes. The PR claims "The result keeps the level played", but this case still shows the device's own level.
     - **Fix:** freeze unconditionally (`level = untracked(this.state.level)`), or gate on the component's own `online()` computed, which also covers forfeit and desync.
